# ซิงก์ผู้ลงทะเบียนเข้า Google Sheets อัตโนมัติ

เป้าหมายคือไฟล์ที่ให้มา `1DUxn8Br2TDwQze-RmxcFBJFMuA1gkQi5qGs8amDCsF8` เฉพาะแท็บ `gid=1971459091` พื้นที่ A:AM รวม 39 คอลัมน์ตรงกับชีตผู้ลงทะเบียนใน Excel Export ใช้รหัสการจองเป็นตัวจับคู่ ไม่ใช้ชื่อหรือ Wcode ซึ่งอาจแก้ไขหรือซ้ำกันได้

## การทำงาน

- ผู้ลงทะเบียนใหม่เพิ่มต่อท้าย ตามลำดับเวลาที่ลงทะเบียน ไม่เรียงใหม่ตามวัน/ช่วงเวลา Consult
- การแก้ Wcode ชื่อเล่น โรงเรียน อีเมล วิชา ช่วงเวลา และสถานะคิว จะอัปเดตแถวของรหัสการจองเดิม
- เมื่อเอาออก/ยกเลิกหรือเก็บรายการแล้ว จะล้างข้อมูล A:AM ของแถวนั้น เหลือแถวว่าง ไม่เลื่อนแถวอื่น ไม่คืน Slot เพียงเพราะซิงก์ และไม่ย้ายหมายเหตุที่ผู้ใช้เพิ่มนอก AM
- คืนการจอง/นำกลับมาแสดงภายหลังจะปรากฏในชีตอีกครั้ง หากเคยล้างแถวแล้วจะเพิ่มท้ายตาราง
- เมื่อเปิดใช้ครั้งแรก จะนำผู้ลงทะเบียนปัจจุบันที่ยังแสดงอยู่เข้าให้ด้วย ไม่ต้องลงทะเบียนใหม่ รายการจบแล้วที่ยังไม่เก็บออกยังรวมอยู่เหมือน Export
- PostgreSQL เป็นข้อมูลหลัก แก้ข้อมูลผ่านหน้า Staff หากแก้ A:AM ในชีตเอง การซิงก์ครั้งถัดไปจะนำข้อมูลจากเว็บกลับมาทับ

Go ทำงานเบื้องหลังโดยตรวจข้อมูลทุก 15 วินาที และส่งเมื่อ revision เปลี่ยน ไม่ต้องเปิดเว็บค้างไว้ ไม่ต้องตั้ง Trigger ใน Apps Script มีการตรวจซ้ำประมาณทุก 5 นาทีเพื่อปรับให้ตรงกับฐานข้อมูล หาก Google/เครือข่ายมีปัญหาจะเพิ่มช่วงลองใหม่สูงสุด 5 นาที ข้อมูลลงทะเบียนยังบันทึกลง PostgreSQL ตามปกติ และรอบลองใหม่จะอ่านข้อมูลล่าสุดทั้งหมด จึงไม่ต้องพึ่งการกด Export

อีเมลและการรีเฟรชหน้าต่าง ๆ ทุก 5 วินาทีใช้ระบบเดิม ซิงก์ชีตเป็น worker แยกและไม่ส่งอีเมลเพิ่ม

## 1. อัปโหลดโค้ดเว็บ

แตก `SPR_Queue_Google_Sheets_Update.zip` แล้วอัปโหลด `backend`, `frontend`, `ops`, `scripts`, `docs` และ README.md ทับที่ root ของ Repo `teaching01-netizen/SPR_Queue` กด Commit changes และรอ Railway ขึ้น Success ชุดนี้รวมการแก้ข้อมูล Staff และ Export ฉบับล่าสุดไว้แล้ว

## 2. สร้าง Apps Script สำหรับชีตแยกอีกโปรเจ็กต์

1. เปิด https://script.google.com/home ด้วยบัญชี Google ที่มีสิทธิ์แก้ไขชีตปลายทาง
2. กด New project ตั้งชื่อ `SPR_Queue Sheets Sync`
3. นำโค้ดจาก `ops/apps-script-sheets/Code.gs` ไปวางทับ Code.gs แล้ว Save (หรือใช้ไฟล์ `SPR_Queue_Google_Sheets_Code.gs` ที่แนบแยก)
4. ไปที่ฟันเฟือง Project Settings → Script Properties → Add script property
5. Property: `APPS_SCRIPT_SECRET` / Value: ค่ากุญแจเดิมที่ตั้งในโปรเจ็กต์ส่งเมลและไฟล์ส่วนตัว `SPR_Queue_Apps_Script_Secret.txt` ไม่ใช่รหัสผ่านอีเมล ไม่ใช่ APP_SECRET ของฐานข้อมูล
6. กลับหน้า Editor เลือก `checkSheetSetup` แล้วกด Run อนุญาตสิทธิ์ Google Sheets ฟังก์ชันนี้ตรวจไฟล์/แท็บและพื้นที่ A:AM เท่านั้น ยังไม่เขียนผู้ลงทะเบียน
7. หากขึ้น `Ready: target tab ...` ถือว่าผ่าน ขั้นนี้จะแสดงชื่อแท็บจริงและ gid ให้ตรวจ

ไฟล์/แท็บตั้งตามลิงก์ที่ให้มาในสองบรรทัดบนของ Code.gs ไม่ต้องเดาชื่อแท็บ ไม่ต้องติดตั้ง Advanced Google Sheets service และอย่าวางโค้ดนี้ทับโปรเจ็กต์ส่งอีเมลเดิม เพราะมี doPost แยกกัน

### หากตรวจแล้วพบข้อมูลเดิม

รอบแรกต้องเป็นพื้นที่ A:AM ที่ว่าง หากขึ้น `TARGET_NOT_EMPTY` สคริปต์จะไม่เขียนทับและไม่ล้างข้อมูลเดิม หยุดไว้แล้วส่งผลตรวจกลับมาเพื่อดูรูปแบบข้อมูลก่อน ไม่ต้องลบข้อมูลเดิมเพื่อให้ผ่านเอง สคริปต์จะเขียนได้เฉพาะแท็บเป้าหมายหลังตรวจว่าปลอดภัย

ยังไม่ได้ตรวจหรือเขียนข้อมูลจริงในชีตผ่านเครื่องมือระหว่างเตรียมชุดนี้ เพราะเครื่องมืออ่าน Google Drive/Sheets ไม่พร้อมใช้งาน ต้องตรวจสิทธิ์และแท็บจริงผ่าน `checkSheetSetup` ก่อนเปิดซิงก์

## 3. Deploy Script เป็น Web app

Deploy → New deployment → Web app → Execute as **Me** → Who has access **Anyone** → Deploy จากนั้นคัดลอก URL ที่ลงท้าย `/exec` ส่งกลับมา ลิงก์นี้เป็นของ Sheets Sync ใหม่ ไม่ใช่ตัวส่งเมล

หากมีการแก้ Code.gs ภายหลัง ต้องใช้ Manage deployments → Edit → New version → Deploy การ Save อย่างเดียวไม่อัปเดตเว็บแอปที่เปิดใช้อยู่

## 4. ตั้งค่า Consult Web บน Railway

หลังโค้ดใหม่ Deploy สำเร็จแล้ว ให้เพิ่มตัวแปรในบริการ Consult Web / production:

| ชื่อ | ค่า |
| --- | --- |
| SHEETS_SYNC_URL | URL /exec ของ Apps Script สำหรับชีต |
| SHEETS_SYNC_SECRET | กุญแจเดียวกับ Script Property APPS_SCRIPT_SECRET |

ไม่เปลี่ยน EMAIL_PROVIDER, APPS_SCRIPT_URL, APPS_SCRIPT_SECRET ของตัวส่งอีเมล ไม่เปลี่ยน APP_SECRET หรือ DATABASE_URL เมื่อส่ง URL กลับมา สามารถเชื่อมสองค่านี้และตรวจ Railway ให้ต่อได้

ระบบนี้ปิดไว้เมื่อยังไม่มีสองตัวแปรนี้ เปิดเฉพาะ APP_ENV=production เพื่อป้องกันฐานข้อมูลทดสอบในเครื่องส่งไปทับชีตจริง หากตั้งค่าผิด ตัวซิงก์จะปิดและมี log `google_sheets_sync_disabled` ส่วนเว็บลงทะเบียนยังทำงาน

## 5. ตรวจผล

- ใน Railway logs จะเห็น `Google Sheets sync enabled` และเมื่อ Google รับการซิงก์แล้วจะเห็น `google_sheets_sync_complete` พร้อม revision โดยไม่ log ข้อมูลผู้ปกครอง
- เปิดแท็บที่ส่งมา ควรเห็นหัวตาราง 39 คอลัมน์และผู้ลงทะเบียนปัจจุบัน
- ทดสอบด้วยรายการที่กำหนดสำหรับทดสอบ: ลงใหม่ → เพิ่มท้าย / แก้ชื่อหรือ Wcode → แถวเดิมเปลี่ยน / เอาออก → A:AM แถวนั้นว่าง
- หากขึ้น `google_sheets_sync_failed` ให้ดู Apps Script Executions และสิทธิ์เจ้าของโปรเจ็กต์ ไม่ต้องให้ Staff ลงทะเบียนซ้ำ

ไม่ใช้ชื่อ Tar หรือ Wcode ใดเป็น blacklist รายการที่ถูกยกเลิก/เก็บออกจะไม่ถูกส่งตามสถานะของรายการนั้น คำถามที่ขึ้นต้นด้วย `=` ส่งเป็นข้อความ ไม่รันสูตร รหัสเลขศูนย์นำหน้าคงเดิม คำขอมี HMAC พร้อมเวลาและตรวจ revision เพื่อไม่ให้ snapshot เก่าทับข้อมูลใหม่ การลองใหม่จับคู่ด้วยรหัสการจอง จึงไม่เพิ่มคนเดิมซ้ำ

สคริปต์รองรับผู้ลงทะเบียนปัจจุบันได้ถึง 1,000 รายการต่อ snapshot (ตารางงานนี้มี 82 slots) และสงวนแถวเดิม/แถวว่างได้รวม 10,000 แถวต่อแท็บ ระบบไม่แก้ชีตอื่นหรือคอลัมน์นอก A:AM และไม่ใช่ระบบสำรองฐานข้อมูล
