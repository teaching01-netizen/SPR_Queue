# คืนสถานะ คืนรหัสคิว และลบรายการยกเลิก — 5 November 2026

อัปโหลดอัปเดตเข้า GitHub และรอ Railway Consult Web Deploy สำเร็จก่อนใช้ฟังก์ชันใหม่ ไม่ต้องล้างฐานข้อมูลหรือเปลี่ยนตัวแปร ใช้บัญชี Admin (RD1) สำหรับคืนสถานะและลบถาวร · ในโหมดทดลองในเครื่อง RD1 เป็น Admin และบัญชีที่เหลือเป็น Operator (หากยังใช้โค้ดรุ่นก่อนหน้า ให้เข้าเมนูนี้ด้วยบัญชี Admin จากการติดตั้งจริง)

## การยกเลิกและอีเมลยืนยัน

การกดยกเลิกรายการจะยกเลิกอีเมลยืนยันที่ยังไม่ได้ส่งไปพร้อมกันในธุรกรรมเดียว และแสดงสถานะอีเมลเป็น Cancelled แทน Failed ถ้าระบบกำลังส่งอีเมลอยู่ การยกเลิกจะถูกปฏิเสธชั่วคราว (NOTIFICATION_BUSY) ให้รอแล้วลองใหม่ เพื่อไม่ให้ผู้ปกครองได้รับอีเมลยืนยันหลังแจ้งยกเลิกแล้ว

การยกเลิกคิวที่สถานะ **กำลังปรึกษา (Serving)** ใช้การยืนยันครั้งเดียวจากปุ่มในหน้าต่าง (ไม่ต้องติ๊กยืนยันเคสเพิ่มและไม่ต้องพิมพ์เหตุผล) ระบบบันทึกเหตุผลกลางว่า “ยุติการปรึกษาระหว่างให้บริการ” ไว้ใน audit และเตือนว่าการยืนยันจะสิ้นสุดการปรึกษาและคืนห้องทันที

## ระบบจัดรหัสใหม่อย่างไร

เมื่อกดบันทึกคิว ระบบอ่านรหัสที่ยังมีคนใช้อยู่จริงในงานและกลุ่มรหัสเดียวกัน แล้วเลือกรหัสว่างที่น้อยที่สุดให้รายการที่ยังไม่มีรหัส โดยเดินตามลำดับรายการที่บันทึก ไม่ใช้ค่าตัวนับเก่าสูงสุด

| รหัสที่ยังใช้ | รหัสของคนใหม่ตามลำดับที่บันทึก |
| --- | --- |
| ไม่มีรหัสเหลือ | 001, 002, 003 ... |
| 001, 002, 005 | 003 แล้ว 004 แล้ว 006 |
| 002 ยังใช้ แต่ 001 ถูกคืน | 001 ก่อน แล้ว 003 |

แยกกลุ่ม B-M, B-V, B-MV, H-M, H-V, H-MV ภายในงานเดียวกัน ไม่เริ่มเลขใหม่แยกตามช่วงเวลา รหัสที่ยังอยู่กับรายการลงทะเบียน รอเรียก กำลังเรียก กำลังปรึกษา ไม่มา หรือจบเคส/เก็บประวัติแล้ว จะไม่ถูกนำไปใช้ซ้ำจนกว่าจะยกเลิกหรือตั้งใจคืนรหัส รายการจริงอื่นไม่ถูกเปลี่ยนรหัสเพื่ออุดช่องว่าง การเรียงลำดับเรียกยังเป็นหน้าที่ของลำดับคิว

## เอาข้อมูลทดสอบออก เช่น Tar

1. เข้า Staff ค้นหาชื่อหรือ Wcode ตรวจสอบวัน เวลา วิชาและรหัสคิวให้ถูกคน
2. ถ้าจบเคส/เก็บประวัติแล้ว เปิดแท็บ **รายการจบแล้ว** กด **คืนสถานะ / คืนที่ว่าง** เลือก **ยกเลิกรายการนี้และคืนที่ว่าง** ใส่เหตุผลและติ๊กยืนยัน (กรณีคิว Serving ไม่ต้องใส่เหตุผล)
3. รายการย้ายไปแท็บ **รายการยกเลิก** คืนทั้งโควตาและรหัสคิว
4. หากต้องการลบออกเลย กด **ลบถาวร / คืนรหัสคิว** ตรวจชื่อและ Wcode ติ๊กยืนยัน แล้วกด **ยืนยันลบรายการนี้ถาวร**

ลบถาวรเฉพาะรายการยกเลิกที่เลือก รวมประวัติและงานเมลของรายการนั้น ดึงกลับไม่ได้ ลิงก์ติดตามเดิมใช้ไม่ได้ ไม่กระทบผู้ปกครองคนอื่น ไม่ส่งอีเมลซ้ำ รหัสที่ถูกคืนจะนำไปใช้กับคนใหม่เมื่อบันทึกคิว ไม่ใช่เมื่อกรอกลงทะเบียน

ปุ่ม **เก็บรายการจบแล้ว** เพียงซ่อนรายการจากหน้าหลัก จึงยังไม่คืนโควตาหรือรหัส ต้องเลือกยกเลิก/คืนสถานะหากใช้รายการนั้นทดลองระบบ

## คืนผู้ปกครองจริงเป็นรอเช็กอิน และคืนรหัสเพื่อจัดใหม่

1. ค้นหารายการจริง เปิด **คืนสถานะ / คืนที่ว่าง** แล้วเลือก **คืนเป็นรอเช็กอิน**
2. ตัวเลือก **คืนรหัสคิวเดิม เพื่อจัดรหัสใหม่ตอนบันทึกคิว** ติ๊กไว้เป็นค่าเริ่มต้น หากยังต้องการเก็บรหัสเดิมของรายการที่ไม่ได้ยกเลิก สามารถเอาติ๊กนี้ออกได้
3. Math + Verbal เลือกวิชาแรกได้ ใส่เหตุผลและติ๊กยืนยันชื่อ แล้วบันทึก
4. กลับไปเช็กอินและบันทึกลำดับคิว ระบบให้เลขว่างตามลำดับที่เลือก เช่น เมื่อ 001 และ 002 ถูกคืนทั้งหมด ผู้จองใหม่สองคนที่จัดก่อนจะได้ 001 และ 002

ยังเก็บ ID ข้อมูลการจองและลิงก์ติดตามเดิม ล้างการเช็กอิน ลำดับคิว ห้องและสถานะปรึกษาที่ทดลองเฉพาะราย พร้อมเก็บข้อมูลก่อนแก้ใน audit หากเลือกคืนรหัส รหัสเดิมไม่ได้ถูกกันไว้ให้เจ้าของเดิมและอาจมีคนอื่นได้รับไปแล้ว

## คืนรายการที่ยกเลิกแต่ยังไม่ได้ลบ

ใช้ **คืนการจอง** ได้สองแบบ:

1. **คืนรอบเดิม** เมื่อช่วงเวลาเดิมยังมีที่ว่างและยังเปิดอยู่ในตาราง
2. **ย้ายไปวัน/รอบใหม่** เลือกวันและช่วงเวลาใหม่ในหน้าต่างคืนการจอง ระบบเก็บข้อมูลการจอง ลิงก์ติดตาม และประวัติวิชาที่ปรึกษาไปแล้วไว้ (เช่น Math + Verbal ที่จบ Math แล้ว) แล้วจองโควตาใหม่ให้ในรอบที่เลือก

หลังคืนต้องบันทึก / จัดคิวใหม่ทุกครั้ง ไม่ดึงรหัสก่อนยกเลิกกลับมา เพราะคนอื่นอาจใช้รหัสนั้นแล้ว ถ้ารอบเดิมเต็มหรือถูกถอดจากตาราง ให้เลือกวันและรอบใหม่ได้ทันที ไม่ต้องแก้ข้อมูลการจองก่อน

รายการยกเลิกจากโค้ดรุ่นเก่าที่ค้างรหัสอยู่จะถูกคืนรหัสเฉพาะเมื่อรหัสนั้นกำลังจะถูกนำไปใช้กับรายการใหม่เท่านั้น รายการยกเลิกอื่นไม่ถูกเขียนทับ และไม่มีการลบรายการจริงหรือรื้อเลขของคนอื่น

## ขอบเขตและการตรวจสอบ

- ใช้การยืนยันเฉพาะ ID และ revision ของคนที่เลือก ถ้าข้อมูลเปลี่ยนระหว่างเปิดหน้าต่างให้เปิดรายการล่าสุดอีกครั้ง
- ถ้ามีงานเมลกำลังส่ง ให้รอแล้วลองใหม่ การคืนสถานะไม่ส่งเมลยืนยันซ้ำ
- รายการยกเลิก/ลบไม่อยู่ใน Excel และข้อมูลซิงค์ไป Google Sheets เมื่อเชื่อมต่อทำงานตามปกติ การซิงค์อัปเดตประมาณ 15 วินาทีเมื่อข้อมูลเปลี่ยน
- หน้า Staff และหน้าติดตามยังอัปเดตทุก 5 วินาที
- ไม่ต้องใช้การรีเซ็ตทั้งระบบ ไม่เปลี่ยนตารางเวลา ไม่แก้ข้อมูลผู้ปกครองอื่น

รอบนี้เตรียมโค้ดและทดสอบด้วยข้อมูลจำลองเท่านั้น ยังไม่ได้แก้หรือลบ Tar หรือผู้ปกครองคนใดบนเว็บจริง
