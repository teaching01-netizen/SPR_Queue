## การนำไฟล์อัปเดตเข้า GitHub

1. แตกไฟล์ SPR_Queue_Schedule_Update.zip
2. เปิด repository teaching01-netizen/SPR_Queue ที่หน้า root เลือก Add file → Upload files แล้วลากไฟล์และโฟลเดอร์ทั้งหมดที่แตกออกมาจาก ZIP เข้าไปทับไฟล์เดิม
3. กด Commit changes แล้วรอ Consult Web บน Railway Deploy สำเร็จ
4. เปิดหน้าจองใหม่หรือโหลดหน้าเว็บใหม่ ตรวจว่า High Level Verbal แสดงเฉพาะ 6 November 2026 และจำนวนรอบ/slots ตรงกับตารางนี้

ไฟล์อัปเดตไม่แก้ APP_SECRET, DATABASE_URL, บัญชี Staff หรือค่าลับบน Railway และไม่ล้างข้อมูลจอง ไม่ต้องสร้างฐานข้อมูลหรือบัญชี Staff ใหม่ การรีเฟรชข้อมูลยังทุก 5 วินาทีตามเดิม

ผลตรวจฐานเว็บจริงก่อนจัดทำชุดอัปเดตวันที่ 30 ตุลาคม: ยังไม่มีรายการจองเดิม จึงไม่มีรายการที่ต้องย้ายช่วงเวลา หากมีรายการจองเข้ามาก่อน Deploy ให้ตรวจรายการเดิมผ่าน Staff และแก้ช่วงเวลาตามที่ตกลงกับผู้ปกครอง ไม่ลบหรือย้ายเวลาอัตโนมัติ

## ผลตรวจอีเมลหลังลงทะเบียน

**มีระบบในโค้ดแล้ว แต่เว็บจริงยังไม่ได้เปิดส่งอีเมล**

- เมื่อตั้งค่าผู้ให้บริการแล้ว การจองสร้างงานส่งอีเมลใน PostgreSQL พร้อมกับบันทึกการจอง และ worker จะทยอยส่งโดยไม่บล็อกหน้าจอง
- อีเมลมีช่วงเวลา Consult, เวลาสัมมนาตามวิชาของ Beginner และปุ่ม Check Queue Status ที่ลิงก์ไปการจองของผู้ปกครองคนนั้น
- มีการลองส่งใหม่เมื่อเกิดข้อผิดพลาด และติดตามสถานะ Pending / Sent / Failed; เมื่อยังปิดอีเมล หน้าจองสำเร็จจะแจ้งให้เก็บลิงก์ติดตามเอง
- ผลตรวจ Railway: ยังคงปิดผู้ให้บริการ และไม่มี EMAIL_FROM / RESEND_API_KEY จึงยังไม่ส่งถึงผู้ปกครองจริง
- โค้ดรองรับ Resend ผ่าน HTTPS ต้องยืนยันโดเมนผู้ส่งและตั้ง EMAIL_PROVIDER=resend, EMAIL_FROM และ RESEND_API_KEY ใน Railway ก่อน แล้วจึงทดสอบรับที่ Inbox/Spam ของผู้รับที่กำหนด

ชุดทดสอบใช้ผู้ให้บริการจำลองผ่าน TLS ตรวจการจอง → งานอีเมล → ผู้รับ/ลิงก์ส่วนตัว/เวลาใหม่ → สถานะ Sent และตรวจว่าเมื่อปิดบริการจะไม่สร้างงานส่ง ไม่ใช่ผลยืนยันการส่งถึงกล่องเมลจริง
