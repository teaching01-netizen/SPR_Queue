# ส่งอีเมลยืนยันการจอง — Warwick Private Consult

## ตั้งค่าบัญชี Warwick แบบกรอกช่องเดียว

บัญชีผู้ส่งเตรียมไว้เป็น `rajchasompob@warwick-institute.com` โดเมนมี MX ของ Google จึงเตรียม Gmail SMTP ให้ (ไม่ใช่ผลตรวจสิทธิ์ของบัญชีหรือการส่งจริง)

1. Login บัญชีนี้ที่ https://myaccount.google.com แล้วเปิด 2-Step Verification หากยังไม่ได้เปิด
2. เปิด https://myaccount.google.com/apppasswords สร้างชื่อ **Warwick Consult** เก็บรหัส 16 ตัวอักษรที่แสดงเพียงครั้งเดียว หากบัญชีองค์กรไม่ให้สร้าง ต้องให้ผู้ดูแล Google Workspace เปิดสิทธิ์หรือใช้ SMTP relay/OAuth ตามนโยบายองค์กร
3. ดาวน์โหลด `Warwick_Update_Queue_Count.sh` ไว้ Downloads เปิด Docker Desktop และ Terminal ในโฟลเดอร์โปรเจกต์เดิม รัน:

```bash
bash ~/Downloads/Warwick_Update_Queue_Count.sh --setup-warwick-email
```

ตัวช่วยตั้ง Host, Port, TLS, Username, From ให้ครบ แล้วถามเฉพาะ App Password (ไม่แสดงบนหน้าจอ) เปิดระบบใหม่และส่งข้อความทดสอบหนึ่งฉบับเข้า Email ผู้ส่งนี้ การตั้งค่าใช้รหัส App Password แทนรหัสเข้าเมลปกติ **อย่าส่ง App Password ในแชท ให้กรอกเฉพาะใน Terminal นี้**

หากอัปเดตโค้ดแล้ว ใช้ `bash scripts/setup-warwick-email.sh` ได้โดยตรง ทดสอบผ่านแล้วลองจองใหม่เพื่อรับปุ่มติดตามคิวจริง รายการจองเดิมเก็บไว้

เครื่องที่เชื่อมต่ออยู่ Offline ณ รอบนี้ จึงไม่ได้แก้ไฟล์บน Mac หรือส่งเข้าบัญชีจริงจากเครื่องผู้ใช้ ระบบพร้อมตั้งค่าเมื่อผู้ใช้รันคำสั่งนี้ด้วย App Password ไม่มีการบันทึกรหัสบัญชีปกติที่ผู้ใช้ส่งมาใน source/ZIP/updater

## อัปเดตในเครื่องโดยเก็บข้อมูลจอง

ดาวน์โหลด `Warwick_Update_Email_Queue.sh` ไว้ Downloads เปิด Docker Desktop แล้วเปิด Terminal ในโฟลเดอร์โปรเจกต์เดิม:

```bash
bash ~/Downloads/Warwick_Update_Email_Queue.sh
```

อัปเดตโค้ดและจอคิว สำรอง source ก่อนเขียน เก็บฐานข้อมูล รายการจอง คิว ลิงก์ติดตาม ตารางกิจกรรม บัญชี Staff และไฟล์ตั้งค่าเดิม ไม่เรียก reset

## ตั้งค่าบัญชีผู้ส่งจริง

ใช้บัญชี SMTP ที่ได้รับอนุญาตให้ส่งอีเมลจากสถาบัน กรอกเฉพาะบนเครื่องใน Terminal:

```bash
bash scripts/setup-email.sh
```

ตัวช่วยถาม Host, Port, Security, Username, Email ผู้ส่ง และ Password/App Password รหัสไม่แสดงบนหน้าจอและไม่ถูกใส่ใน command history บันทึกใน `.env.smtp` ที่อ่านได้เฉพาะเจ้าของ แล้วเปิดระบบใหม่

ถ้าทำอัปเดตและตั้งค่าในคำสั่งเดียว:

```bash
bash ~/Downloads/Warwick_Update_Email_Queue.sh --setup-email
```

| ค่า | ตัวอย่าง Gmail / Google Workspace |
| --- | --- |
| SMTP host | smtp.gmail.com |
| SMTP port | 587 |
| Security | starttls |
| SMTP username | Email ผู้ส่งแบบเต็ม |
| From email | Email ผู้ส่งที่บัญชีได้รับอนุญาตให้ใช้ |
| Password | App Password สำหรับแอปนี้ ตามสิทธิ์ของบัญชีและนโยบายองค์กร |

อีกทางเลือกคือ Port 465 กับ Security `tls` ตามที่ผู้ให้บริการกำหนด รองรับ TLS 1.2+ และตรวจ certificate ไม่รองรับการส่งผ่าน plaintext หรือ OAuth-only SMTP ในรุ่นนี้

Google Workspace อาจต้องให้ผู้ดูแลระบบเปิดสิทธิ์สำหรับ App Password/SMTP ใช้รายละเอียดจากผู้ให้บริการของบัญชีนั้นโดยตรง:
- https://support.google.com/a/answer/176600
- https://support.google.com/accounts/answer/185833

ไม่ต้องกรอกรหัสในแชทหรือส่งไฟล์ `.env.smtp` ให้ผู้อื่น บัญชี Staff RD/SM เป็นคนละชุดกับบัญชีส่งเมล

## ทดสอบส่ง

ส่งข้อความทดสอบหนึ่งฉบับ โดยพิมพ์ Email ผู้รับเมื่อระบบถาม:

```bash
bash scripts/test-email.sh
```

ข้อความทดสอบแสดงว่าไม่ใช่การจองจริง ปุ่มในข้อความทดสอบไปหน้าจอง ไม่มีการสร้างรายการจองหรือรหัสคิว

จากนั้นลอง **จองรายการใหม่** ด้วย Email ที่ตรวจกล่องได้ จะได้รับอีเมลยืนยันจริงและปุ่ม `Check Queue Status` ของรายการนั้น รอ worker ประมาณ 3 วินาทีต่อรอบ ตรวจ Inbox/Spam และสถานะ Email ในหน้ารายละเอียด Staff (Sent / Failed / Pending)

SMTP server ยอมรับข้อความยังไม่รับประกันว่าปลายทางใส่ Inbox การตั้งค่า From/domain และนโยบายของผู้รับมีผล หากส่งไม่สำเร็จระบบ retry สูงสุด 5 ครั้ง การจองยังมีผล ปัญหาบัญชีหรือรหัสควรแก้ใน `.env.smtp` ผ่านตัวช่วยเดิม ไม่พิมพ์ secret ลง log

รายการเดิมที่จองตอนปิดอีเมลจะไม่ถูกส่งย้อนหลังอัตโนมัติ เพื่อไม่ส่งข้อความทดสอบเก่าให้ผู้ปกครองโดยไม่ตั้งใจ

## หน้าตาและเนื้อหา

`backend/internal/consult/email_template.go` ใช้ template เดียวกับการส่งจริง ดูตัวอย่างได้จาก `Warwick_Email_Preview.html`

- คำขึ้นต้นถึงผู้ปกครองตาม Nickname
- Beginner มีกรอบสัมมนารวมตามวิชาที่จอง ข้อมูลวันที่/เวลามาจาก config; Math + Verbal แสดงทั้งสองวิชา
- High Level แสดง Private Consult โดยไม่มีสัมมนา Beginner
- Consult แสดงวันที่ วิชา รูปแบบ และ **ช่วงเวลา Consult: xx:xx - xx:xx** พื้นเหลือง แสดงทั้งรอบที่จอง ไม่แสดงเวลารายคนที่ยังไม่ได้กำหนด
- มีปุ่มสีแดง `Check Queue Status` และลิงก์ข้อความสำรองที่ใช้ token ส่วนตัวของการจองจริง ไม่ใช้ URL Script เดิม
- มีข้อความธรรมดาสำรองสำหรับแอปที่ไม่แสดง HTML ชื่อและข้อมูลผู้ใช้ถูก escape
- ไม่มีการใส่เวลาลงทะเบียนสัมมนาจากรูปเก่า เพราะยังไม่ได้กำหนดใหม่ หน้าตาอาจต่างเล็กน้อยตาม Gmail/Outlook/แอปผู้รับ

## ลิงก์จากเครื่องทดสอบและจากระบบจริง

ปัจจุบันเว็บอยู่ `http://127.0.0.1:8080` ลิงก์ในอีเมลจึงเปิดได้บนเครื่องที่รันเว็บเท่านั้น แม้ส่งอีเมลจริงแล้วก็ยังไม่สามารถให้ผู้ปกครองเปิดจากมือถือหรือเครื่องอื่นได้

ก่อนส่งให้ผู้ปกครองใช้งานจริง ต้องเปิดเว็บผ่าน URL ที่เข้าถึงได้จากภายนอก ตั้ง `PUBLIC_URL` ของระบบเป็น HTTPS URL นั้น แล้วสร้าง/ส่งอีเมลใหม่ อีเมลที่ส่งไปก่อนเปลี่ยน URL จะไม่เปลี่ยนลิงก์ตามอัตโนมัติ ใช้ deployment production และ SMTP ตาม `docs/POSTGRESQL.md` ชุดบัญชี RD/SM ปัจจุบันเป็น local-test

## จอคิวสำหรับผู้ปกครอง

Math / Verbal แสดงคิวที่กำลังเรียกหรือปรึกษา ด้านล่างแสดงคิวถัดไปสูงสุด 2 รายการ เฉพาะสถานะ Waiting ที่เช็กอิน มีรหัสคิว และบันทึกลำดับสำหรับห้องปัจจุบันแล้ว แสดงรหัสและช่วงเวลา ไม่เปิดชื่อ Email โรงเรียน หรือคำถาม

ขณะมีคิว active ใช้เฉพาะรอบเดียวกัน หากห้องยังว่างเลือกจากรอบแรกที่มีคิวพร้อม ไม่ข้ามไปดึงคิวรอบอื่นมาปน ไม่แสดง No-show/Cancelled/Completed หรือ Combined ที่ยังไม่จัดลำดับวิชาถัดไป ลำดับอาจเปลี่ยนตาม Staff จึงยังไม่รับประกันว่าเป็นลำดับเรียกที่ตายตัว

หน้าติดตามส่วนตัวมีตัวนับคิวแล้ว ใช้คำว่า “เหลืออีก X คิวถึงคุณ” (คิวถัดไป=1, กำลังเรียก/ปรึกษาของตัวเอง=0) นับตามลำดับพร้อมเรียกหลังคิวล่าสุด รวมตัวเอง ไม่นับ No-show/Cancelled/Completed แยกวิชาปัจจุบันของ Combined และอัปเดตตาม Staff; ยังไม่แปลงเป็นนาที รายละเอียดใน QUEUE_COUNT_TH.md
